# Agentic How-To 05: Configure AI Agents

## Purpose
Make every agent tool in the repo (Antigravity/AGY, Claude Code, Cursor, GitHub Copilot, generic `.agents`) load the Spec-Rails rules and the CLI-free `/opsx-*` workflows, and keep the setup consistent for the whole team.

## Preconditions
- Spec-Rails installed ([01](01-bootstrap-new-project.md)). Present: `.agents/skills/spec-rails/SKILL.md`, `openspec/spec-rails/AGENTS.md`, `openspec/spec-rails/WORKFLOW.md`.
- You are on a `chore/` branch for any change below.

## What `init` already gives you
- `.agents/skills/spec-rails/SKILL.md`: the skill runbook (managed).
- `openspec/spec-rails/AGENTS.md` (always-on guardrails) and `WORKFLOW.md` (protocol), outside files that `openspec update` regenerates.
- Generated `explore`, `propose`, `apply`, `archive`, `sync`, `update` skills/commands/prompts for each tool chosen with `--tools`, rewritten to CLI-free bodies. Other generated workflows are left untouched and logged as needing the `openspec` CLI.

## Command and skill names
Each `/opsx-<name>` command has an equivalent `openspec-<name>` skill (`/opsx-apply` = `openspec-apply-change`, `/opsx-archive` = `openspec-archive-change`, `/opsx-propose` = `openspec-propose`, `/opsx-explore` = `openspec-explore`). Use whichever name your tool exposes; use the `openspec-*` skill when `/opsx-*` is absent. Gate rules apply identically (see [02](02-drive-feature-lifecycle.md)).

## Steps

1. **List what is installed**:
   ```bash
   ls .agents/skills .claude/skills .github/skills .github/prompts .cursor 2>/dev/null
   ```
2. **Add tools** (only when needed): run `openspec init --tools agents,claude` (needs the pinned CLI) only if `openspec/` is absent; otherwise add the tool with the openspec CLI per its docs, then **always** re-run `npx spec-rails init` so the new files get CLI-free bodies. Verify no generated skill still calls the CLI except those logged as "no port":
   ```bash
   npx spec-rails init | grep -i "no port"
   ```
3. **Antigravity (AGY)**
   - Project level: nothing to do; `.agents/skills/spec-rails/SKILL.md` is discovered. For rules, copy the guardrails:
     ```bash
     mkdir -p .agents/rules
     cp openspec/spec-rails/AGENTS.md .agents/rules/spec-rails.md
     ```
     Re-copy after every `init` that changes `AGENTS.md` (it is a copy, not a link).
   - Global (human's machine): link the plugin and skill into `~/.gemini/config/plugins` and `~/.gemini/config/skills`.
   - Subagents: `Workspace: 'share'` or the worktree path (see [03](03-parallel-worktrees-multi-agent.md)).
4. **Claude Code**: add to `CLAUDE.md` at the repo root:
   ```markdown
   # Spec-Rails Protocol
   Always consult `openspec/spec-rails/WORKFLOW.md` and `openspec/spec-rails/AGENTS.md` before starting work.
   - Never edit code on main/master; use feat/<id>-<slug>, fix/<slug> or chore/<slug>.
   - Never tick a Review Gate checkbox; stop for human approval at every gate.
   - Red test first, never committed alone; >= 95% coverage and >= 95% mutation kill.
   ```
   Optionally copy the skill: `mkdir -p .claude/skills/spec-rails && cp .agents/skills/spec-rails/SKILL.md .claude/skills/spec-rails/`.
5. **Cursor / other IDEs**: import `openspec/spec-rails/AGENTS.md` into `.cursorrules` or the tool's rules file.
6. **GitHub Copilot**: prompts live in `.github/prompts/`; skills in `.github/skills/`. They are rewritten by `init` like any other layout.
7. **Commit the footprint** so every contributor and CI see the same skills: commit `.agents/`, `.claude/`, `.github/skills` and `openspec/spec-rails/`; do not git-ignore them. Keep skills only for tools in use; delete unwanted `opsx-*` aliases (they come back after `openspec update`).
   ```bash
   git add -A && git commit -m "chore: configure agent tooling"
   ```
8. **After any `openspec update`**: re-run `npx spec-rails init`, then `git diff` to confirm the CLI-free bodies are back.

## Expected outputs / verification
- Each configured tool lists a Spec-Rails skill/rule that mentions `openspec/spec-rails/WORKFLOW.md`.
- Asking the agent to `/opsx-propose` creates `openspec/changes/<id>-<slug>/.openspec.yaml` without invoking an `openspec` binary.
- `npx spec-rails init` reports only `skipped` after the setup is committed.

## Failure modes
| Symptom | Cause | Fix |
| :-- | :-- | :-- |
| `/opsx-*` command missing | Tool not in `--tools`, or duplicate aliases removed | Use `openspec-*` skill names, or add the tool and re-run `init` |
| Skill complains `openspec: command not found` | Skill regenerated by `openspec update` | Re-run `npx spec-rails init` |
| `.agents/rules/spec-rails.md` is stale | Manual copy not refreshed | Re-copy `AGENTS.md` |
| Teammate's agent ignores rules | `.agents/` or `.claude/` git-ignored | Remove the ignore entry and commit |
| Agent edits `docs/agentic-how-tos/*` | Managed files | Revert; `init` overwrites them anyway |

## Hard rules for agents
- [ ] Rules in `AGENTS.md` apply in every tool: branch check first, never tick gates, Red before Green, `--ff-only` merges, worktree cleanup.
- [ ] Never hand-edit managed files; change the source in the spec-rails package instead and re-run `init`.
- [ ] Do not leave generated skills that depend on the `openspec` CLI when a port exists; re-run `init`.
- [ ] Subagents: one worktree each, no polling loops (dispatch and end the turn), never touch another stream's files.
- [ ] Do not commit secrets or machine-specific global config (`~/.gemini/...`).
