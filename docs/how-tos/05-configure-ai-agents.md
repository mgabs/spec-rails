# How-To: Configure AI Agents with Spec-Rails

This guide explains how to install and enable Spec-Rails for Antigravity (AGY), Claude Code, and Cursor.

---

## 1. Antigravity (AGY) Integration

### Option A: Global Installation
Link the `spec-rails` plugin and skill into your user config:

```bash
mkdir -p ~/.gemini/config/plugins ~/.gemini/config/skills
ln -sfn /path/to/spec-rails ~/.gemini/config/plugins/spec-rails
ln -sfn /path/to/spec-rails/skills/spec-rails ~/.gemini/config/skills/spec-rails
```

The agent will discover `spec-rails` automatically across all projects.

### Option B: Project-Level Installation (Automatic via Installer)
Running `npx spec-rails init` on an OpenSpec project automatically installs `.agents/skills/spec-rails/SKILL.md` along with `openspec/spec-rails/AGENTS.md` and `openspec/spec-rails/WORKFLOW.md` (all outside files regenerated by `openspec update`). If you also use `.agents/rules/`, copy `openspec/spec-rails/AGENTS.md`:

```bash
mkdir -p .agents/rules
cp openspec/spec-rails/AGENTS.md .agents/rules/spec-rails.md
```

Commit `.agents/` and `openspec/spec-rails/` so the entire team's agents follow Spec-Rails rules.

### OpenSpec CLI & `/opsx-*` Command Discipline
- Create changes with `openspec new change <id>-<slug>` (normalizing work item dots to hyphens: `W1.2` → `w1-2-<slug>`).
- For planning, run `openspec instructions <artifact> --change <id>-<slug>` step-by-step, pausing after each gate for explicit human review and checkbox approval before drafting the next artifact.
- Run `/opsx-apply` and `/opsx-archive` (`openspec archive <id>-<slug> --yes`) only after Gate 3 is ticked by a human. Agents never self-tick human Review Gate boxes.

---

### Command Names & Skill Footprint

- Every `/opsx-<name>` command has an equivalent `openspec-<name>` skill (for example `/opsx-apply` = `openspec-apply-change`). Adopters may remove the duplicate `opsx-*` alias skills, so either name is valid; use the `openspec-*` skills when `/opsx-*` is absent.
- Commit `.claude/`, `.agents/` and `.github/skills` instead of ignoring them, so every contributor and CI sees the same agent skills.
- Keep skills only for the tools in use. `openspec update` regenerates the `opsx-*` aliases; delete them again if unwanted.
- Optionally copy the `spec-rails` skill into `.claude/skills/` for Claude Code.

## 2. Claude Code Integration

Add the Spec-Rails rules to `CLAUDE.md` in your project root:

```markdown
# Spec-Rails Protocol
This repository enforces Spec-Driven, Testing-Railed Development (Spec-Rails).
Always consult `openspec/spec-rails/WORKFLOW.md` before starting work.
- Never edit code without human sign-off at Gates 0–3.
- Always use feature branches (`feat/<id>-<slug>`) or isolated worktrees (`.worktrees/*`).
- Always write failing tests first (Red) before implementation (Green).
- Enforce >= 95% coverage and >= 95% mutation kill score on core modules.
```

---

## 3. Cursor / General IDE Integration

For IDE rules (e.g. `.cursorrules`), import the rules from `openspec/spec-rails/AGENTS.md`.
